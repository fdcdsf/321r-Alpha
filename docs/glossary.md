# Глоссарий (простыми словами)

Непонятное слово из документации — искать здесь. Если слова нет — добавьте его сюда же.
Общая картина системы — [architecture.md](architecture.md).

## Общее

| Термин | Простыми словами |
|---|---|
| Нода / узел | Один сервер (VPS) в кластере. Имена (a, b, c…) и роли (state/work/bulk) задаются в инвентаре |
| Кластер | Несколько серверов, работающих как одна система |
| Кворум | Большинство голосов (из 3 — минимум 2). Без кворума решения не принимаются |
| Правило 2K+1 | Чтобы пережить K одновременных потерь, «старших» (менеджеров) надо ≥ 2K+1 |
| RPO | Сколько данных теряем при аварии (секунды: асинхронная репликация) |
| RTO | Сколько времени на восстановление (замена ноды ~1 час; полное — часы) |
| Дрилл | Учение: специально ломаем и проверяем, что обещанное работает ([drills.md](drills.md)) |
| Runbook | Инструкция «что делать при X» для уставшего человека в 3 часа ночи |
| Идемпотентность | Скрипт можно запускать повторно — не сломает уже сделанное |
| CP / AP (CAP) | Выбор при расколе: согласованность и остановка записи (CP) против доступности (AP). Кластер — CP: изолированная нода молчит |
| Инвентарь | Файл `inventory.conf` с серверами, приложениями и настройками установки |
| control-нода | Нода, на которой работает Telegram-бот команд; алерты шлёт любая нода |

## Сеть

| Термин | Простыми словами |
|---|---|
| Mesh (меш) | Личная сеть серверов поверх интернета — как один этаж с лифтом ([amnezia-wg.md](amnezia-wg.md)) |
| WireGuard / AmneziaWG | Протокол «туннеля» между серверами. AmneziaWG — версия, спрятанная от DPI |
| wg0 | Сетевой интерфейс меша (10.66.0.x) |
| HPK (HeaderProtectionKey) | Общий секрет обфускации меша — один на все ноды |
| reresolve | Переспрашивание DNS: IP сервера сменился — пир переподключается сам |
| DDNS | Автообновление DNS-записей при смене IP (`ddns.sh`) |
| Multi-A | Одно имя → несколько IP. Браузер перебирает их при отказе — живучесть входа |
| VIP 10.66.0.99 | «Вечный» адрес баз данных на каждой ноде: за ним прокси на текущего первичного |
| DNS-01 / HTTP-01 | Способы подтвердить домен для сертификата. HTTP-01 при multi-A невозможен — везде DNS-01 |
| Wildcard | Сертификат/зона на `*.домен` — один на все поддомены сразу |
| CNAME / A / NS | Типы DNS-записей: «синоним», «адрес», «здесь свой DNS-сервер» |
| DPI | Оборудование провайдера, режущее протоколы по виду трафика |

## Pangolin (слой входа)

| Термин | Простыми словами |
|---|---|
| Pangolin | Панель+прокси: по имени домена доводит посетителя до сервиса через туннель ([pangolin.md](pangolin.md)) |
| Gerbil | Компонент Pangolin: SNI-прокси + WireGuard-туннели для сайтов (порт 51820) |
| Traefik | Веб-прокси перед сервисами: HTTPS, сертификаты, маршруты |
| Newt / сайт-агент | Программа на стороне сервиса (дом, VPS): держит туннель и ходит к цели |
| Ресурс | Публичный адрес `имя.домен` → список целей (куда идти) |
| Цель (target) | Конкретный сервер/порт сервиса за туннелем; у неё health-check |
| Health-check (HC) | Проверка «цель жива?». Без здорового HC цель не маршрутизируется! |
| Exit node | Нода кластера, к которой прицеплён туннель сайта |
| ACME-клиент | Нода, выдающая сертификаты Let's Encrypt (строго одна на кластер!) |
| `pangolin-wildcard-repair.sh` | Скрипт лечения wildcard-сертификатов и DNS-записей (запускается по cron) |
| trusted-upstreams | Список адресов, которым Pangolin доверяет (все IP нод) |

## Вычисления и управление

| Термин | Простыми словами |
|---|---|
| Docker Swarm | Встроенный оркестратор Docker: держит сервисы на плаву при смерти серверов |
| Manager / Worker | «Старшие» (принимают решения, голосуют) и «младшие» серверы Swarm. Все ноды кластера — старшие |
| Ingress-порт | Порт, слушающий на всех нодах и доводящий до сервиса, где бы тот ни жил |
| Constraint / метки | Правила «где жить» сервису (role=state/work/bulk, svc.<app>) |
| Stack / стек | Набор сервисов, выкатываемый одним манифестом |
| Komodo | Панель управления серверами и стеками ([api.md](api.md)) |
| Core / Periphery | Komodo: центр (живёт в Swarm, перелетает сам) и агенты на серверах |
| Periphery onboarding-key | Одноразовый ключ привязки агента к Core |
| Констрейнт по памяти | Правило «не селить на слабую ноду чужие инстансы» |

## Данные

| Термин | Простыми словами |
|---|---|
| Primary / Standby | «Первичный» (пишут все) и «дублёр» (копия на случай беды) ([databases.md](databases.md)) |
| Streaming-репликация | Первичный непрерывно копирует изменения на стендбаи (секунды отставания) |
| basebackup / pg_basebackup | Полная копия данных PG для нового стендбая |
| WAL | Журнал изменений PG: восстановление «до момента аварии» |
| Promote | Команда «ты теперь первичный» (db-guard её и даёт) |
| Timeline (таймлайн) | Номер «ветки истории» PG; расхождение лечится пересборкой стендбая |
| MongoDB RS (реплика-сет) | Группа Mongo-серверов с автоматической копией данных |
| Арбитр | Голосующий участник RS без данных (для кворума из 2 серверов) |
| db-guard | Скрипт-«старший по подъезду»: назначает первичного, переключает прокси, фенсит изолированных |
| Фенсинг (фенс) | Изоляция сервера, потерявшего связь с большинством: молчит, но данные целы |
| D1 | Модель кластера: один инстанс БД = одно приложение |
| S(X) | Список серверов приложения X (где живут его базы) |
| apps.d | Реестр приложений: кому какие базы и где |
| Valkey | Кэш (форк Redis) перед Pangolin |
| restic | Программа бэкапов с дедупликацией; репозитории — `/var/lib/backup-repos` ([backups.md](backups.md)) |
| R2 | Облачное хранилище — не используется; копии живут на нодах и физическом носителе |
| Верификация восстановления | Еженедельная проверка «копии действительно читаются и запускаются» |

## Безопасность

| Термин | Простыми словами |
|---|---|
| SOPS + age | Шифрование секретов для git (в репозитории — только шифр) ([security.md](security.md)) |
| fail2ban | Автобан тех, кто ломится в SSH |
| ufw / DOCKER-USER | Файрвол ОС / цепочка фильтрации Docker (порт здесь — контейнерный!) |
| 2FA / recovery-коды | Второй фактор входа / запасные одноразовые коды |
| Скомпрометированный ключ | Ключ, побывавший в чате или логах: считается утёкшим — немедленно заменить ключи и пересоздать доступы |
| Памятка владельца | Файл со всеми паролями и ключами; только офлайн-хранение, в git не кладётся |
