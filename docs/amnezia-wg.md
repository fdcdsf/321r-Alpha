# AmneziaWG — меш кластера

Меш AmneziaWG соединяет все серверы кластера напрямую (N×N): трафик сервисов, баз данных и администрирования идёт по внутренним адресам 10.66.0.x в обход интернета. Протокол обфусцирован — DPI не отличает туннель от обычного трафика. Здесь описаны устройство меша, параметры обфускации, проверка рукопожатий, восстановление и запасной путь на обычном WireGuard.

## Как устроен меш

- Интерфейс `wg0`, UDP-порт **51821**, конфиг `/etc/amnezia/amneziawg/wg0.conf` — утилита `awg-quick` ищет конфиги только в этом каталоге (не в `/etc/wireguard/`).
- У каждой ноды свой mesh-адрес `10.66.0.x/32` и общий VIP `10.66.0.99` (для слоя БД, см. [databases.md](databases.md)).
- Полный меш: на каждой ноде по пиру на каждую соседнюю ноду, `PersistentKeepalive = 25` — линк держится живым и быстро показывает смерть соседа.
- Ключи: `/etc/wireguard/privatekey` и `/etc/wireguard/publickey`; приватный ключ не покидает ноду.
- Подъём: `awg0.service` → `/usr/local/sbin/awg0-up.sh` (до 6 попыток up/down); остановка — `awg-quick down wg0`. Порт 51821/udp открывает межсетевой экран.

Требования: полная виртуальная машина (KVM; на OpenVZ/LXC модуль ядра не поставить), x86_64, ядро ≥ 6.7, не менее 512 МБ RAM, DKMS и заголовки ядра работающего ядра.

## Обфускация (протокол AmneziaWG 3.1)

Симметричные параметры обязаны совпадать на всех нодах:

- `HeaderProtectionKey` (HPK) — секрет кластера. Генерирует установщик (файл `hpk` в каталоге секретов установщика), значение живёт в `wg0.conf`. Важно: разный HPK на нодах — линк молчит без единой ошибки.
- `S1–S4 = 12` — размеры фрейминга хендшейка.
- `Jc = 4`, `Jmin = 50`, `Jmax = 1000` — junk-пакеты (отправительская сторона; полная согласованность между нодами не обязательна, но штатная установка держит её).

Не задаются: `RandomTrailers` (резко режет скорость — десятки раз), `DisableCookies` (снимает защиту от флуда хендшейков). Параметр `I1` — запасная эскалация, если DPI начнёт резать трафик.

Частая ошибка: при повторной установке поверх работающего меша сгенерировать новый HPK нельзя — живой меш перестанет сходиться. Установщик берёт HPK из существующего `wg0.conf` и не перетирает его.

## Установка

Штатный путь — шаг `mesh` установщика (см. [quickstart.md](quickstart.md)). При ручной установке:

```bash
mkdir -p /etc/apt/keyrings
curl -fsSL "https://keyserver.ubuntu.com/pks/lookup?op=get&search=0x75C9DD72C799870E310542E24166F2C257290828" \
  | gpg --dearmor -o /etc/apt/keyrings/amnezia.gpg
echo "deb [signed-by=/etc/apt/keyrings/amnezia.gpg] https://ppa.launchpadcontent.net/amnezia/ppa/ubuntu focal main" \
  > /etc/apt/sources.list.d/amnezia.list
apt update && apt install -y amneziawg
dkms status        # ожидание: amneziawg/<версия>, <ядро>: installed
modprobe amneziawg # модуль обязан загрузиться
```

Сборка DKMS занимает 5–15 минут. Частая ошибка: apt «успешно» ставит пакет, а DKMS молча пропускает сборку без заголовков ядра — тогда `modprobe amneziawg` падает и меша нет. Проверяйте `dkms status` и `modprobe`; при необходимости `dkms autoinstall`. Штатная установка сама выбирает серию PPA под ваш дистрибутив.

## Роль меша в кластере

По мешу ходят служебные потоки: слой БД (VIP `10.66.0.99`), Pangolin (trusted-upstreams включают mesh-адреса всех нод), VPN-ноды к панели Remnawave, межнодовый SSH и Telegram-бот. Меш не публикует сервисы наружу — это транспорт кластера; внешние порты открыты только там, где это требуется по [security.md](security.md).

## Проверка рукопожатий

```bash
awg show wg0 latest-handshakes   # у всех пиров ненулевое время
awg show wg0                     # endpoint, transfer, peers
ping -c1 -W2 10.66.0.x           # mesh-адрес соседней ноды
```

Установщик проверяет оба пункта: рукопожатия со всеми соседями и ping до каждого mesh-адреса. Если рукопожатий меньше числа пиров — смотрите `awg show wg0` на обеих сторонах: сначала смотрите endpoint и latest handshake, затем firewall (51821/udp) и IP в DNS.

## Восстановление

- `awg0-up.sh` при старте системы повторяет подъём до 6 раз; следите за `systemctl status awg0.service`.
- В конфиге пир задан именем (`<имя>.<домен>:51821`), в ядре живёт IP. Таймер `reresolve-dns.timer` каждые 45 с перезапрашивает DNS и обновляет endpoint'ы пиров на лету. Смена IP провайдера или A-записи (ddns) не требует правки `wg0.conf`.
- Замена сервера: перегенерируйте ключи на новой ноде и обновите соответствующий `[Peer]` на остальных (см. [replace-node.md](replace-node.md)).
- Рукопожатие есть, а трафик не идёт — проверьте `Address`/`AllowedIPs` в обоих направлениях и отсутствие лишних маршрутов.

## Запасной путь: обычный WireGuard

Если протокол AmneziaWG заблокируют полностью, тот же `wg0.conf` поднимается обычным WireGuard (пакет `wireguard`): уберите из `[Interface]` параметры обфускации (`Jc`, `Jmin`, `Jmax`, `S1`–`S4`, `HeaderProtectionKey`), порт 51821 оставьте. Если заблокируют IP ноды — смените A-запись; меш переподключится сам в течение 45 с.

## Частые проблемы

| Симптом | Причина | Лечение |
|---|---|---|
| Линк молчит, ошибок нет | Разные HPK/S-параметры на нодах | Выровняйте параметры обфускации на всех нодах |
| `modprobe amneziawg` падает | Не собран DKMS (нет заголовков ядра) | `dkms autoinstall`, при необходимости ребут после обновления ядра |
| `awg-quick` не находит конфиг | Конфиги ищутся в `/etc/amnezia/amneziawg/` | Положите `wg0.conf` в этот каталог |
| После ребута меш не сошёлся | Служба не поднялась или устаревший endpoint | `systemctl status awg0.service`; таймер reresolve обновит endpoint'ы |
| Одна нода «отвалилась» и не возвращается | Сменился её IP, а DNS ещё не обновился | Дождитесь reresolve (45 с) или проверьте A-запись |
