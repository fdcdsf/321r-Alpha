# Ресурсы и профили

Продукт работает и на скромном железе, но у него честный бюджет памяти и профили, под
которые он укладывается. Этот документ — паспорт потребления компонентов, правила бюджета,
профили S/M/L и минимальные требования железа. Планируйте кластер по нему до покупки
серверов.

## Паспорт памяти компонентов

| Компонент | RSS (установившееся) | Обязателен? | Лимит (вшит в compose) |
|---|---|---|---|
| ОС + dockerd/containerd/systemd | ~250–350 МБ | да | — |
| Панель Pangolin (Node.js) | 365–400 МБ | да (или вынести панель) | heap 320 + `mem_limit: 512m` |
| Панель Remnawave (3 процесса) | 440 МБ | да (VPN) | heap 320 + `mem_limit: 640m` |
| Страница подписок (Node.js) | 95 МБ | да (VPN) | heap 128 + `mem_limit: 256m` |
| mongod (дата-нода или арбитр) | 215–380 МБ (растёт с прогревом кэша) | только Komodo | `mem_limit: 640m`, кэш 0.256 |
| remnanode (Xray) | 105–127 МБ | да (VPN-продукт) | — |
| PostgreSQL (standby) | 20–25 МБ | да | `mem_limit: 512m` |
| PostgreSQL (primary) | до 70 МБ | да | `mem_limit: 512m` |
| traefik | 48–72 МБ | да | — |
| gerbil | 25–42 МБ | да | — |
| db-proxy (haproxy) | 44–55 МБ | да | `mem_limit: 128m` |
| mtproto (хостовый) | 11–13 МБ | опционально | — |
| Uptime Kuma | 122 МБ | опционально | — |
| Komodo Core | 60 МБ | опционально | — |
| Valkey ×2 (Pangolin/Remnawave) | 11–18 МБ каждый | да | `mem_limit: 128m` |
| Zabbix: server / web / агент | 53 / 44 / 30 МБ (+ БД pg-zabbix 58–155) | опционально | — |

**Пиковый разовый жор:** каждый запуск `mongosh` ≈ 200 МБ (Node.js внутри!) — поэтому
никаких mongosh в циклах: только пачками и с кешем.

**CPU:** на холостом ходу load 1.0–1.5 на одном ядре. Реальный трафик (VPN/Telegram)
добавляет нагрузку — это нормальная работа продукта.

## Правила бюджета

1. **У каждого контейнера есть `mem_limit`.** cgroup-OOM убивает контейнер (он
   перезапустится), а не роняет ноду. Для Node.js — ещё и `NODE_OPTIONS=--max-old-space-size`.
2. **Потолок кучи Node.js обязателен:** панель Remnawave из коробки ставит
   `--max-old-space-size=16384` (16 ГБ!) — на слабой ноде это путь к OOM всей машины.
   Экономия от капа скромная (−35…−100 МБ), но безопасность — главная причина.
3. **Кэш WiredTiger MongoDB не ужимать ниже 0.25** — mongo не стартует (`BadValue`).
   Поэтому mongo — самый «дорогой» необязательный компонент: на слабых нодах его либо
   не ставим, либо одним инстансом.
4. **Никаких тяжёлых форков в циклах** (mongosh ≈ 200 МБ пик; docker CLI тоже не бесплатен).
5. **Journald ограничен** (`SystemMaxUse=200M`), логи контейнеров режутся logrotate по
   200 МБ, `vm.swappiness=10`.
6. **Тяжёлое — на большие ноды или вовне кластера** (см. профили).

## Профили

Мастер установщика спрашивает профиль ресурсов S/M/L. Профиль S, кроме того, не открывает
публичные веб-порты (80/443/8443/2053/2087) — ядро без панелей наружу.

### S — минимум (ноды 1 vCPU / 1–2 ГБ)

| Компонент | Решение |
|---|---|
| Меш + слой БД + вход (gerbil/traefik) + VPN-ноды | обязательно на всех нодах |
| Панели (Pangolin, Remnawave) | вовне кластера или на отдельной большой ноде; для Remnawave — режим `connect` мастера (панель дома за Newt через Pangolin) |
| Komodo + mongo | не ставить (управление через CLI/SSH), либо mongo одним инстансом |
| Zabbix, Kuma | выключить (внешние проверки) |
| mtproto | опционально (+13 МБ — дёшево) |

Бюджет ноды: ОС 250 + gerbil/traefik 80 + PG 25–70 + db-proxy 50 + Xray 110 + mtproto 13
≈ **530–570 МБ** → укладывается в 1 ГБ. Рекомендация: swap 512 МБ как подушка всплесков.
Нода с панелью Remnawave: +440 МБ → этой ноде нужно ≥ 2 ГБ.

### M — средний (ноды ≥ 2 ГБ, одна ≥ 4 ГБ)

- панели на самой большой ноде; mongo одним инстансом (Komodo есть, но без RS) —
  либо RS, если все ноды ≥ 2 ГБ;
- Kuma на одной ноде; Zabbix — по желанию.

### L — всё включено (одна нода ≥ 4 ГБ)

Полный состав: панели, mongo RS с арбитром, страница подписок, Kuma, Komodo, mtproto,
Zabbix. Пиковая нода укладывается примерно в 3 ГБ — планируйте с запасом.

## Честные минимальные требования

| Конфигурация | Минимум железа |
|---|---|
| Ядро кластера (меш + БД + вход + VPN), панели вовне | **3 × (1 vCPU, 1 ГБ)**, swap 512 МБ рекомендуется |
| + панель Remnawave на VPS | нода панели ≥ 2 ГБ |
| + Komodo (mongo) | ноды mongo ≥ 2 ГБ (пол кэша WiredTiger) |
| + Zabbix HA | хотя бы один сервер ≥ 4 ГБ |
| Всё сразу (профиль L) | как минимум одна нода ≥ 4 ГБ |

Общие требования: полная виртуализация (KVM/VMware/Hyper-V — контейнерные OpenVZ/LXC
не подойдут), ядро ≥ 6.7 (установщик сам ставит свежее ядро и перезагружает ноду при
необходимости). ОС: Debian 12/13, Ubuntu 22.04/24.04/26.04.

## Частые ошибки планирования

- **Все ноды по 2 ГБ и полный состав** — swap-шторм, mongo без первичного. Установщик
  предупредит: ставьте профиль S или возьмите сервер побольше.
- **mongo на нодах < 2 ГБ** — OOM-риск (WiredTiger + mongosh): не рекомендуется.
- **Панели на всех нодах «на всякий случай»** — каждая копия ест сотни МБ; панель
  нужна в одном экземпляре, вход и так держится на всех нодах.
