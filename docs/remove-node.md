# Удаление ноды

Убрать сервер из кластера можно в любой момент и без потерь данных: правило «нет единственных копий» гарантирует, что на уходящей ноде не осталось ни одной базы. Главное — не сам демонтаж, а вычистка упоминаний узла: `nodes.map`, реестр приложений, Pangolin, DNS. Минимум — 3 узла в кластере; пережить K потерь могут только ≥ 2K+1 менеджеров Swarm.

См. также: [Добавление ноды](add-node.md), [Замена сервера](replace-node.md), [Базы данных](databases.md).

## Когда убираем ноду

- закончилась аренда сервера;
- сервер стал плохим (диск, сеть) — обычно лучше заменить: [replace-node.md](replace-node.md);
- кластер сужается с 5 до 3.

## Шаг 1. Проверить, что на ноде нет баз

```bash
cat /etc/db/apps.d/*.yaml                       # placement каждого приложения
docker node inspect <имя-в-swarm> --format '{{json .Spec.Labels}}'
```

- Если уходящая нода входит в `placement` приложения — **сначала уберите её инстанс**: `bash /usr/local/bin/app-member.sh remove <app> <узел>` сузит `placement`, остановит инстанс и обновит прокси (у Mongo ещё и уберёт члена из реплика-сети). Вручную — правка `/etc/db/apps.d/<app>.yaml` на всех нодах плюс `bash /usr/local/bin/db-add.sh <app>` (см. [databases.md](databases.md)).
- Если на ноде живёт первичный — перенесите его заранее (`app-move.sh`) либо дождитесь, пока db-guard назначит нового (≤2 мин).
- Практическое правило: **на уходящей ноде не должно остаться ни одной базы**. Данные старого инстанса можно удалить потом — спешить не нужно.

## Шаг 2. Swarm: drain → remove

```bash
docker node update --availability drain <имя-в-swarm>   # задачи Swarm переехали
docker node rm <имя-в-swarm>                            # --force, если нода мертва
```

Проверка: `docker node ls` — узла нет, сервисы работают на выживших.

## Шаг 3. Вычистить узел из кластера (обязательный хвост)

1. **Инвентарь** — удалить сервер из `install/inventory.conf` на сервере-мастере: дальше шаги `dns` и `mesh` работают по инвентарю.
2. **`nodes.map` на всех оставшихся нодах** — удалить строку узла. Частая ошибка: забывают — и цепь назначений db-guard ходит через мёртвый узел (задержки и ошибки в журнале).
3. **`apps.d/`** — сверить, что узла нигде нет (placement сузили в шаге 1).
4. **Pangolin** — удалить сайт-агент `cluster-<alias>` и его токены (панель → Sites); убрать IP узла из `trusted-upstreams` (проще повторить шаг `pangolin` установщика — он пересчитает список по инвентарю).
5. **DNS** — удалить A-записи узла `<alias>.<base>` и `vpn-<alias>.<base>`. Строку в хабе `dns.<base>`, а также лишние A у `<base>`, `*.<base>`, `dns.<base>`, `tg.<base>` расчистит повторный шаг `dns` по инвентарю. CNAME и NS не трогать.
6. **Мониторинг и бэкапы** — снять ноду с проверок и из цепочки бэкапов; убедиться, что правило «2 соседние» ([backups.md](backups.md)) выполняется для оставшихся.
7. **Меш** — удалить пир уходящей ноды из `wg0.conf` живых узлов (они просто молчат, но конфиг должен быть чистым). Проще всего перегенерировать меш шагом `mesh` установщика — по уже очищенному инвентарю.

## Шаг 4. Финальная проверка

```bash
docker node ls                       # N-1 Ready, кворум есть
awg show wg0                         # рукопожатия только между живыми
curl -sk https://pangolin.<base>/ -o /dev/null -w '%{http_code}\n'   # 200
journalctl -t db-guard -n 20         # без «не отвечает» и ошибок цепи
```

Пересчитайте кворумы: менеджеров ≥ 2K+1 для ожидаемого числа одновременных потерь.

## Чек-лист «нода убрана»

- [ ] На ноде нет баз: placement сузили, `db-add`/`rs.remove` выполнены
- [ ] drain → rm: `docker node ls` чистый, сервисы переехали
- [ ] `nodes.map` вычищен на всех нодах ★ (самый частый забытый шаг)
- [ ] `apps.d` не ссылается на узел
- [ ] Pangolin: агент удалён, `trusted-upstreams` пересчитан
- [ ] DNS: записи узла удалены, хаб расчищен
- [ ] Мониторинг и бэкапы обновлены, «2 соседние» выполняется
- [ ] Кворумы пересчитаны (2K+1)

## Если нода «сама ушла» (мертва физически)

То же самое, но drain не нужен: сразу `docker node rm --force <имя-в-swarm>`, дальше шаги 3–4. Если это потеря, а не плановое сужение, — действуйте по [replace-node.md](replace-node.md): замена с тем же именем и mesh-адресом проще, чем новая нода.
