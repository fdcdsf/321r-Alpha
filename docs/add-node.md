# Добавление ноды

Кластер принимает новые сервера свободно: минимум 3 узла, верхнего предела нет, имена нод задаёте вы. Новая нода — это строка в инвентаре и повторный прогон шагов установщика: шаги идемпотентны и уже настроенные узлы не ломают. Домен в примерах — `<base>` (например, `example.com`), имена нод — короткие (`a`, `b`, `c`, `d`).

См. также: [Удаление ноды](remove-node.md), [Замена сервера](replace-node.md), [Базы данных](databases.md), [DNS и сертификаты](dns-and-tls.md).

## Правила перед добавлением

1. **Новая нода вступает менеджером Swarm.** Воркеров в кластере нет: db-guard голосует метками, а метки ставят только менеджеры. Пережить K потерянных узлов могут только ≥ 2K+1 менеджеров.
2. **Виртуализация — полная VM (KVM).** На OpenVZ/LXC AmneziaWG не встанет: нужен модуль ядра.
3. **RAM — от 1 ГБ** (иначе установщик предупредит). Полный состав — панели, mongo и базы — требует хотя бы одну ноду ≥4 ГБ; на серверах по 2 ГБ берите профиль `S`.
4. **Данные нового узла — только вторые копии.** Ни одна база не должна иметь единственную копию на новой ноде.
5. В кластере всегда остаётся не меньше 3 узлов.

## Шаг 1. Инвентарь и DNS

Добавьте сервер в `install/inventory.conf` на сервере-мастере (каталог `/opt/321r`):

```bash
NODES=(
  "a 203.0.113.10 10.66.0.1 state"
  "b 203.0.113.20 10.66.0.2 work"
  "c 203.0.113.30 10.66.0.3 bulk"
  "d 203.0.113.40 10.66.0.4 work"
)
```

Поля строки: имя (оно же hostname и имя в Swarm), публичный IP, mesh-адрес из `10.66.0.0/24`, роль (`state` | `work` | `bulk`).

DNS-записи новой ноды создаст шаг `dns`: A `d.<base>` и её строку в хабе `dns.<base>`. Если ведёте зону руками — создайте обе записи заранее; без них `ddns.sh` не найдёт что обновлять. CNAME и NS-записи не трогаются вовсе: вся схема — в [dns-and-tls.md](dns-and-tls.md).

## Шаг 2. Повторный прогон установщика

```bash
cd /opt/321r
./install/install.sh --from=preflight --to=swarm    # доступ, базовая подготовка, меш, Swarm
./install/install.sh --from=db --to=db              # слой БД
./install/install.sh --from=dns --to=dns            # DNS-записи и ddns на всех нодах
./install/install.sh --from=pangolin --to=komodo    # Pangolin (сайт-агенты) + Komodo (periphery)
./install/install.sh --check                        # автоприёмка
```

Первый запросит пароль нового сервера один раз и заложит ключ кластера. Полный список шагов для `--from=`/`--to=`: `preflight, base, mesh, swarm, db, backup, tgbot, dns, pangolin, komodo, remnawave, zabbix, check, handover, harden` — повторить можно любой диапазон.

Что шаги делают для новой ноды:

- `base` — скрипты и systemd-юниты, hostname = имя из инвентаря, ssh на порту 2222, ufw, fail2ban;
- `mesh` — AmneziaWG, общий секрет обфускации (HPK) берётся из работающего меша, пиры прописываются на всех нодах (полный меш N×N);
- `swarm` — join менеджером и метки `role`, `name`;
- `db` — VIP `10.66.0.99` на wg0, ufw-зона контейнеров, каталоги, предварительный pull образов, `nodes.map`;
- `pangolin`, `komodo` — конфиги (в том числе `trusted-upstreams` со всеми IP нод), сайт-агент `cluster-d`, periphery с ключом onboarding.

## Шаг 3. nodes.map на всех нодах (обязательно)

Шаг `db` создаёт `/etc/db/nodes.map` только там, где файла ещё нет: на старых нодах карта остаётся прежней. Допишите строку новой ноды на **всех** узлах, включая новую:

```bash
# формат: alias mesh-адрес имя-в-swarm (сверьте с docker node ls)
echo 'd 10.66.0.4 d' >> /etc/db/nodes.map
```

Важно: не запускайте `db-prep.sh` на ноде без карты — он создаст карту по умолчанию, и цепь назначений db-guard разъедется. Правильную карту собирает шаг `db` из инвентаря.

## Шаг 4. Базы данных новой ноды

По умолчанию БД на новой ноде не заводятся: инстансы живут только на узлах `placement` ([databases.md](databases.md)). Если нода нужна приложениям как реплика:

1. допишите её в `placement` записи `/etc/db/apps.d/<app>.yaml` (на всех нодах);
2. запустите `bash /usr/local/bin/db-add.sh <app>` — PostgreSQL догонит узел сам (`pg_basebackup` от первичного);
3. для Mongo расширение реплика-сети делается вручную (`rs.add`) — db-add инициализирует только новую сеть.

`db-guard.timer` на новой ноде включает шаг `db` — проверьте: `systemctl is-active db-guard.timer`.

## Шаг 5. Приёмка

```bash
awg show wg0 latest-handshakes    # рукопожатия со всеми N-1 соседями
docker node ls                    # все Ready, роли проставлены
ss -ltn | grep 10.66.0.99         # VIP слушает порты БД
curl --resolve pangolin.<base>:443:<IP-новой> https://pangolin.<base>/ -o /dev/null -w '%{http_code}\n'
journalctl -t db-guard -n 20      # без ошибок и «не отвечает»
```

Ответ `curl` — 200. Дополнительно: nmap с соседней ноды — таблица портов соответствует [справочнику](reference.md); бэкапы — включить ноду в цепочку «2 соседние» ([backups.md](backups.md)); мониторинг — добавить в проверки ([monitoring.md](monitoring.md)).

## Чек-лист «новая нода принята»

- [ ] A-запись `<alias>.<base>` и строка в хабе `dns.<base>` созданы (ddns поддерживает их сам)
- [ ] Меш: рукопожатия со всеми N-1 узлами и пинг до каждого через `10.66.0.0/24`
- [ ] Swarm: `docker node ls` — Ready, роль проставлена, нода — менеджер
- [ ] `nodes.map` обновлён на всех нодах
- [ ] db-prep выполнен; при необходимости `db-add.sh <app>` догнал новые узлы
- [ ] Pangolin: сайт-агент `cluster-<alias>` онлайн, `pangolin-wildcard-repair.sh <IP-новой>` выполнен
- [ ] Periphery Komodo онлайн, мониторинг и бэкапы видят ноду
- [ ] nmap с соседа соответствует таблице портов

## Типичные ошибки

| Ошибка | Последствие | Как избежать |
|---|---|---|
| Не обновили `nodes.map` на старых нодах | цепь назначений db-guard ходит мимо новой ноды, голоса неполные | шаг 3 |
| Не тот HPK | обфускация не совпадает — линк молчит | штатный установщик берёт HPK из меша; при ручной сборке — значение `HeaderProtectionKey` из `wg0.conf` живой ноды |
| Нода вступила воркером | db-guard не голосует и не назначает первичного | всегда менеджер (правило 2K+1) |
| Забыли `pangolin-wildcard-repair.sh` после старта Pangolin | ресурсы второго уровня отвечают 404 | [dns-and-tls.md](dns-and-tls.md) |
| Не обновили `trusted-upstreams` | часть трафика режется как недоверенная | повтор шага `pangolin` пересчитывает список |
| Расширили `placement`, но не запустили `db-add` | на новой ноде нет ни данных, ни прокси-блока | шаг 4 |
