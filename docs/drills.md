# Дриллы (учения по отказам)

Кластер обещает пережить потерю ноды и месяц без присмотра. Дрилл — проверка, которая
превращает обещание в факт: мы намеренно ломаем часть системы и сверяем поведение с нормой.
Непроверенная отказоустойчивость — сказка. Расписание и регламент эксплуатации —
[operations.md](operations.md).

## Правила проведения

1. Дрилл-блок команд — одним куском из одного терминала; первая строка проверяет ноду-жертву
   (`hostname`, `docker node ls`) — чтобы команда не ушла не на тот сервер.
2. Останавливать docker — только `systemctl stop docker docker.socket` (иначе socket оживляет
   демон).
3. `mongosh` руками — только отдельным контейнером (см. [troubleshooting.md](troubleshooting.md)).
4. Перед дриллом: `git commit`, свежие бэкапы, рабочее окно (не ночной пик нагрузки).
5. После дрилла: протокол по шаблону ниже + все находки — в [troubleshooting.md](troubleshooting.md)
   и в правила установщика.

## Каталог дриллов

| Дрилл | Что имитируем | Норма | Период |
|---|---|---|---|
| Смена IP | провайдер сменил IP ноды | ddns ≤2 мин, reresolve ≤45 с, кластер жив | ежеквартально |
| Промоушен PG | смерть первичного PG | следующий по цепи за ≤2 мин (типично 10–40 с), прокси и метки Swarm корректны | ежеквартально |
| Назначение Mongo | смерть primary mongod | назначение ≤1 мин (типично ~25 с), приложения пишут через VIP | ежеквартально |
| Фенсинг | изоляция ноды (потеря кворума) | фенс ≤60 с, большинство пишет, возврат без потерь | ежеквартально |
| «Нода ложится» | падение ноды с сервисами (стоп docker) | Swarm переносит задачи (Core, Kuma), без фенса | ежеквартально |
| Панель Remnawave лежит | потеря панели VPN | маски 200, Xray жив, панель 503, возврат ~30 с | ежеквартально |
| «IP заблокирован» | блокировка IP ноды | клиенты multi-A уходят на живые ноды; блокировать по контейнерным портам! | ежеквартально |
| Панель падает (cgroup-OOM) | смерть панели под нагрузкой | ingress не страдает, панель поднимается ~5 с | ежеквартально |
| Потеря большинства (2 из 3) | нет кворума Swarm | фенс 60 с → выживание по команде владельца → авто-восстановление ~90 с | ежеквартально |
| Дрилл данных | смерть первичного PG при живой панели | db-guard переключает ≤2 мин, панель пишет дальше | ежеквартально |
| Восстановление из бэкапа | потеря дата-центра | новый кластер + данные из копий (RTO часы) | ежеквартально |
| Перенос приложения (app-move) | миграция между нодами | даунтайм ~10–20 с, без потери данных | при изменениях |
| Слабая нода | на ноде мало RAM | нет чужих инстансов, память в норме | при смене ролей |
| Ребут-тест (все серверы) | полное отключение стойки | самоизлечение всего за ≤10 мин | раз в полгода |

## Как проводить ключевые дриллы

### Промоушен PG

```bash
# 1) проверить жертву (одним блоком из одного терминала):
hostname; docker ps --format '{{.Names}}' | grep '^pg-'
# 2) остановить инстанс-первичный:
cd /opt/db/pg-pangolin && docker compose down
# 3) метрика: время до нового первичного
journalctl -t db-guard -f   # маркер «ПРОМОУШЕН»
```

Проверки: VIP отвечает на запись, прокси на всех нодах указывают на нового первичного
(`апстрим прокси →` в логе db-guard), метки Swarm обновлены. Вернувшийся старый первичный
становится стендбаем сам; при ошибке таймлайна — `pg-rebuild-standby.sh`.

### Фенсинг

Изолировать ноду (например, временно перекрыть mesh-трафик) и убедиться: в течение ≤60 с
появляются DROP-правила в DOCKER-USER, изолированная нода молчит, остальные пишут. После
снятия изоляции — «ФЕНС снят», стендбай догоняет по WAL, потерь нет.

### Потеря большинства (2 из 3)

Остановить docker на двух нодах (`systemctl stop docker docker.socket`). Норма: фенс
выжившей ноды, затем по команде владельца `/survival` в боте (или `survival.sh`) — выжившие
инстансы поднимаются. После возврата нод — авто-восстановление ~90 с и обязательная сверка
целостности: «шаг назад», пересборка стендбаев.

### Восстановление из бэкапа

Собрать новый кластер по [deploy.md](deploy.md), затем данные из restic-репозиториев и дампов
([backups.md](backups.md), [doctrine-3-2-1.md](doctrine-3-2-1.md)). Сверить RTO и RPO; каждое
препятствие — в [troubleshooting.md](troubleshooting.md) (раздел восстановления из basebackup).

### Ребут-тест

Перезагрузить все серверы и засечь время самоизлечения: меш, Swarm, БД, Komodo, сертификаты,
панели. Норма — всё восстановилось без человека за ≤10 минут.

## Формат протокола

Протокол каждого дрилла храните в этом каталоге рядом с документом.

```markdown
## Дрилл <название> (<дата>): ПРОЙДЕН / НЕ ПРОЙДЕН
**Цель:** ...
**Что делали:** (блоки команд с указанием нод)
**Метрики:** (фактические времена против нормы из таблицы)
**Находки:** что показало учение и что надо исправить.
**Что автоматизировать/исправить:** ...
```

## Календарь

- Ежеквартально: полный набор дриллов + восстановление из бэкапа.
- Раз в полгода: ребут-тест всех серверов.
- После каждого изменения архитектуры: точечный дрилл затронутой подсистемы.
