# Развёртывание с нуля

Весь кластер 321r ставится одной командой с первого сервера: мастер спрашивает всё
нужное, раскатывает шаги на все серверы параллельно и на выходе выдаёт готовый кластер
с автоприёмкой. Этот документ разбирает вопросы мастера, ход установки, повторный запуск
и поведение при перезагрузках.

## Одна команда

```bash
# от root на первом сервере:
curl -fsSL https://raw.githubusercontent.com/fdcdsf/321r-Alpha/master/install/bootstrap.sh | bash
```

Установщик скачивает репозиторий в `/opt/321r`, запускает мастер и ведёт все серверы
через шаги. Каждый шаг идемпотентен: проверяет, сделано ли уже, делает работу, оставляет
проверяемый след; при сбое останавливается с понятным сообщением «что сломалось и как
чинить». Повторный запуск ничего работающего не сломает.

Либо с ноутбука: `git clone` репозитория, заполнить `install/inventory.conf` и запустить
`./install/install.sh` — та же машина шагов.

## Что спросит мастер

1. **Сколько серверов** (минимум 3) и для каждого: короткое имя (a, b, c…) и IP-адрес.
   Mesh-адреса (10.66.0.x) и роли (первый — state, последний — bulk, остальные — work)
   назначаются автоматически.
2. **Нода команд бота (control)** — по умолчанию второй сервер.
3. **Приложения (базы данных)** — по умолчанию `pangolin` (pg, 5432), `remnawave` (pg,
   5433), `komodo` (mongo, 27017); раскладка реплик считается от числа серверов.
   Можно ввести свой список строками: `имя engine(pg|mongo) порт placement`.
4. **Токен Telegram-бота** (от @BotFather) и **chat id владельца** (от @userinfobot).
5. **Домен** (можно пусто — тогда ставится только ядро) и **Cloudflare API-токен**
   (можно пусто).
6. **Pangolin**: автоматически настроить админа, сайты и доступ к Komodo? [Y/n];
   **лицензия Pangolin EE** — скрытый ввод (Enter = без лицензии).
7. **Remnawave**: `install` — панель на кластере, или `connect` — существующая панель
   (HTTPS-адрес + API-токен; в этом режиме отдельный PostgreSQL для Remnawave на VPS
   не создаётся).
8. **WARP `.conf`** — путь к файлу для каждого сервера (пусто = загрузить через бота позже).
9. **Ваш публичный SSH-ключ** (пусто = оставить парольный вход — небезопасно).
10. **Профиль ресурсов S/M/L** [L] — см. [resources.md](resources.md).
11. **Zabbix HA** [y/N] — панель и мониторинг на всех VPS; нужен хотя бы один сервер ≥ 4 ГБ.

Мастер сохраняет ответы в `install/inventory.conf` (права 600) — при повторном запуске
их можно править, установщик перечитывает файл.

## Ход установки (шаги)

| Шаг | Что делает | Проверка |
|---|---|---|
| preflight | ключ межнодового доступа, разовая закладка ключей по паролям, проверка виртуализации/памяти/ядра | «нет» = стоп с причиной |
| base | пакеты, UTC+NTP, Docker, firewall, fail2ban, лимиты логов; скрипты в `/usr/local/bin/` | ssh на 2222 со всех нод |
| mesh | AmneziaWG 3.1 (PPA+DKMS), wg0.conf со общим HeaderProtectionKey, VIP 10.66.0.99 | handshake со всеми пирами, пинг 10.66.0.x |
| swarm | init на первой, join менеджерами на остальных, метки ролей, DOCKER-USER | `docker node ls` = N × Ready |
| db | каталоги `/etc/db`, `apps.d`, `db-add` для приложений, haproxy на VIP, `db-guard.timer` | запись через VIP, `pg_stat_replication`, `rs.status()` |
| backup | restic-репозитории на 2 соседних нодах, cron бэкапов и проверок | репозитории готовы |
| tgbot | бот, алерты, дозор, дайджест | меню в Telegram |
| dns | записи Cloudflare (multi-A, CNAME, NS-делегация), ddns, учётки сертификатов | зона отвечает |
| pangolin | стек pangolin+gerbil+traefik, первичная инициализация, сайты-агенты | `https://<base>` = 200 со всех IP |
| komodo | Core (swarm-стек) + periphery на всех нодах, ресурс в Pangolin | `komodo.<base>` = 200 |
| remnawave | панель, VPN-ноды, маскировка (Xray/mtproto), страница подписок | `vpn-<узел>.<base>`, `sub.<base>` |
| zabbix | только при ZABBIX_MODE=install: server HA, web, агенты, алерты | `zabbix.<base>` = 200 |
| check | автоприёмка по чек-листу | все строки `✓` |
| handover | «🔐 Памятка владельца» в Telegram и в `/root/321r-pamyatka-*.txt` | файл получен |
| harden | ваш ключ на все ноды, парольный вход отключён, fail2ban включён | вход вашим ключом работает |

Установка занимает обычно 15–30 минут; с перезагрузкой ядра и полным составом панелей —
до часа. DKMS-сборка модуля AmneziaWG — 5–15 минут на ноду.

## Что проверять на выходе

- отчёт автоприёмки — все строки `✓`; итог печатается в конце;
- памятка владельца в Telegram: пароли, ключи, ссылки, `setup token` Pangolin — сохраните
  её отдельно от серверов;
- меню бота отвечает, утренний дайджест придёт в 09:00;
- вручную: `https://<base>/` открывается с любого IP нод, сертификат содержит `*.<base>`.

Подробный чек-лист приёмки — в [quickstart.md](quickstart.md) и [drills.md](drills.md).

## Повторный запуск и `--from=`

```bash
./install/install.sh                     # мастер или готовый inventory.conf
./install/install.sh my.conf             # установка по готовому инвентарю
./install/install.sh --from=db           # продолжить с шага db
./install/install.sh --from=pangolin --to=pangolin   # повторить один шаг
./install/install.sh --check             # только автоприёмка
./install/install.sh --manifest          # перегенерировать cluster.yml из инвентаря
```

Допустимые имена шагов: `preflight|base|mesh|swarm|db|backup|tgbot|dns|pangolin|komodo|
remnawave|zabbix|check|handover|harden`. Секреты и инвентарь переживают повторное
скачивание установщика: `/opt/321r/install/secrets/` и `inventory.conf` сохраняются.

## Авто-продолжение после ребута

Если на шаге base выясняется, что ядро устарело и заголовков для него больше нет в
репозиториях, установщик ставит свежее ядро и перезагружает ноду — без этого DKMS не
соберёт модуль AmneziaWG. Остальные ноды установщик перезагружает и ждёт сам.

Важно: если перезагружаться должна **мастера-нода**, установка не прерывается — на ней
ставится служба `321r-resume.service`, которая после загрузки сама продолжает установку
с шага mesh и удаляет себя при успехе. Лог продолжения: `/var/log/321r-install-resume.log`.
Если в нём строка «ПРОДОЛЖЕНИЕ НЕ УДАЛОСЬ» — повторите вручную:

```bash
bash /opt/321r/install/install.sh --from=mesh
```

## Секреты

Секреты генерируются на нодах и остаются на нодах; через рабочую машину проходит только
зашифрованный одноразовый пакет. Пароли PostgreSQL/MongoDB каждый раз генерирует сама
нода (`/etc/db/secrets/<app>.env`, umask 077); HeaderProtectionKey меша и
`server.secret` Pangolin — один на весь кластер; введённые пароли серверов используются
один раз для закладки ключа и не сохраняются.

## Чего одна команда не делает

- не покупает VPS и не заводит аккаунты (делается руками владельца, один раз);
- не включает 2FA и не прячет recovery-коды (человеческое);
- не восстановит данные с ноды, сгоревшей без бэкапов ([backups.md](backups.md)).
